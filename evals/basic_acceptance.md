# Source to Brief Basic Acceptance

## Prompt

Use `source-to-brief` to turn a source packet into a Markdown research brief for a downstream Open Design artifact.

The source packet may be product, policy, business, technical, literary, research, or mixed-source material.

## Pass Conditions

- Starts with a clear title and reading path.
- Confirms downstream artifact target before drafting when unspecified.
- Confirms brief language before drafting when unspecified.
- Confirms depth before drafting when unspecified.
- Prompts the user that Markdown can work well in Open Design preview.
- Mentions that Markdown remains readable in GitHub, GitLab, Obsidian, Typora, VS Code, or plain text.
- Writes a `.md` file by default.
- Reconstructs the source around problem, claims, evidence, implications, open questions, and downstream artifact recommendations.
- Uses a narrative structure appropriate to the material type.
- Does not force every source into the same outline.
- Preserves important definitions.
- Preserves important distinctions.
- Preserves important argument steps.
- Preserves important evidence.
- Preserves important examples.
- Preserves important limitations.
- Preserves important conclusion boundaries.
- For classical, literary, narrative, or canonical texts, preserves the source's own order, form, narrative movement, imagery, rhetoric, and historical context.
- Does not become a source ledger.
- Does not become a paragraph summary.
- Does not become a generic abstract.
- Does not collapse unfamiliar or difficult material into a brief abstract.
- Asks before using external scholarly supplementation for complex, broad, or controversial material.
- If external scholarship is used, references are listed and clearly marked.
- If external scholarship is not used, the brief says so briefly.
- Does not claim unsupported facts.
- Does not fabricate citations.
- Does not fabricate authors, titles, years, page numbers, DOIs, URLs, quotes, statistics, or source attributions.
- If Markdown enhancements are requested, they remain restrained and portable.
- Runs the P0 gates in `references/checklist.md`.
- Saves the declared primary output, usually `brief.md`.
- Names the likely next Open Design artifact path when the source supports one.

## Strong Output Signals

- The brief is useful to the user's next artifact-building step.
- Source claims and supplemental context are distinguishable.
- External supplementation is clearly labelled when used.
- Reusable content blocks are concrete enough to feed a deck.
- Reusable content blocks are concrete enough to feed a prototype.
- Reusable content blocks are concrete enough to feed a PM spec.
- Reusable content blocks are concrete enough to feed a dashboard.
- Reusable content blocks are concrete enough to feed a decision room.
- Reusable content blocks are concrete enough to feed a design brief.
