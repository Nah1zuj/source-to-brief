# Material-Type Structures

Use these structures to adapt the default design intelligence brief to the source genre. Do not let them replace the default output schema unless the source material genuinely requires it.

## User Research Or Interview Packet

Structure around:

- user groups
- jobs to be done
- pain points
- observed behavior
- repeated patterns
- contradictions
- quotes or excerpts, only when stable and supplied
- design opportunities
- risks and unknowns

## Competitive Scan

Structure around:

- category norms
- competitor promises
- feature patterns
- differentiation gaps
- pricing or positioning signals
- visual or interaction conventions
- opportunity spaces
- evidence confidence

## Market, Business, Or Strategy Report

Structure around:

- market or business shift
- segments
- demand signals
- value pools
- constraints
- strategic implications
- artifact recommendations
- caveats

## Policy, Compliance, Or Legal Source

Structure around:

- governing rule or constraint
- affected users or operators
- required disclosures, consent, data, or process requirements
- design limitations
- risk areas
- unresolved interpretation questions

## Technical Source

Structure around:

- capability
- limitation
- implementation requirement
- data, cost, latency, reliability, or security constraint
- feasibility implication
- product risk
- testable assumptions

## Meeting Notes Or Internal Memo

Structure around:

- decisions made
- unresolved questions
- stakeholder positions
- constraints
- next actions
- artifact implications
- source confidence

## Multi-Source Folder

Structure around:

- user's stated goal
- source hierarchy
- shared problem
- convergences and disagreements
- strongest evidence
- source gaps
- integrated artifact translation

Do not produce one mini-summary per file unless the user asks for a dossier. Build an integrated brief.

## Academic Or Discipline-Heavy Source

Use this secondary mode when the source is explicitly academic, scholarly, literary, canonical, or discipline-heavy.

Structure around:

- research or interpretive problem
- key concepts
- method, evidence, text, or argument
- findings or claims
- limitations
- implications for the downstream artifact

Use `discipline-adapters.md` only when this secondary mode is needed.
