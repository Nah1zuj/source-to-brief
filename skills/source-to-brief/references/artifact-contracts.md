# Artifact Contracts

Use these contracts before drafting artifact recommendations. The brief should provide only the elements supported by supplied sources, with assumptions and gaps clearly labelled.

## Deck

The brief should provide:

- audience and decision context
- narrative thesis
- 3-5 evidence-backed claims
- strongest evidence
- tension or stakes
- recommended slide storyline
- caveats

## Prototype

The brief should provide:

- target user
- scenario
- user goal
- pain point
- core flow
- required screens or states
- interaction requirements
- testable assumptions

## PM Spec

The brief should provide:

- problem statement
- user stories
- functional requirements
- non-goals
- constraints
- dependencies
- success metrics
- risks and open questions

## Dashboard

The brief should provide:

- decision to monitor
- key metrics
- dimensions
- data sources
- update cadence
- alert conditions
- interpretation caveats

## Decision Room

The brief should provide:

- competing options
- decision criteria
- evidence for each option
- tradeoffs
- risks
- unresolved questions
- recommended next decision

## Design Brief

The brief should provide:

- background
- audience
- problem
- goals
- constraints
- tone or experience principles
- deliverables
- success criteria
